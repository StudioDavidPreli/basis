# Contract: Basis consumes Cadence

Source of truth for names and values: `cadence-consumer-reference.md` (pulled
from Cadence source 2026-09-16). Package: `cadence-tokens@2.0.1` on npm. 2.0.0
shipped the per-preset dist files behind an exports map that did not name them,
so both imports below were refused by every resolver; 2.0.1 opens `./dist/*`.
Pin `^2.0.1`, never `2.0.0`.

## What Basis imports

One preset on the sheet, three on the embeds
(`decisions/2026-10-05-presets-for-the-embeds.md`).

```ts
// app/layout.tsx (server)
import 'cadence-tokens/dist/standard/cadence.css'
// exposes --cadence-duration-*, --cadence-ease-*, --cadence-delay-*,
// --cadence-scale-*, --cadence-spring-*, --cadence-duration-scalar,
// plus a @media (prefers-reduced-motion: reduce) block carrying the resolution.
import '@/styles/presets.css'
// GENERATED by scripts/presets-css.mjs from each preset's cadence.css in the
// package, `:root` rewritten to `:root[data-preset="<id>"]`. No value is
// typed by hand; the file is rebuilt before every build and checked by a test.

// lib/motion/tokens.ts (client) — the ONLY module that imports these
import * as standard from 'cadence-tokens/dist/standard/cadence.motion.js'
import * as snappy from 'cadence-tokens/dist/snappy/cadence.motion.js'
import * as cinematic from 'cadence-tokens/dist/cinematic/cadence.motion.js'
import { REDUCED_MOTION_RESOLUTION } from 'cadence-tokens'
```

Preset is Standard. On `/embed/*` only, `?preset=snappy|cinematic|standard`
(default `standard`) sets `data-preset` on `<html>` from the inline script before hydration, and
the hook reads it as it reads `data-reduce-motion`. It never leaks into
component code: components read `useMotionTokens()` and `--cadence-*`, never
a module or an attribute. Reduced motion flattens every preset: the override
in `app/globals.css` is restated at `:root[data-reduce-motion='1']`
specificity, after the presets.

One scoped exception, the tool's introduction
(`decisions/2026-10-16-the-introduction-runs-cinematic.md`): the welcome
dialog runs Cinematic while the sheet around it runs Standard, because the
preset belongs to the use, not the product. `styles/presets.css` therefore
also scopes each preset to any element carrying `data-preset`, under motion
only (`:root[data-reduce-motion='0'] [data-preset]`), so the element and its
`::backdrop` inherit that preset's properties and reduced motion still
flattens them through the root. The hook takes the preset as its one
argument there, `useMotionTokens('cinematic')`, and reads the root
everywhere else. Still no module and no value in component code.

## What Basis does not import

- `presets.<id>.ambient` — the Motion Tiles clock vocabulary. Not interaction motion.
- `--motion-*` — Cadence's own site CSS. Not in the package.
- `--feedback-*` — Cadence tool chrome timing. Not tokens, not exported.
- `deviations` — absent in dist files; if present, ignore.
- Anything visual. Cadence has none, and Basis must not expect any. The one
  exception is four color stocks restated from Cadence's `color.css` for a
  framed `/embed/*` (`decisions/2026-10-14-cadence-stocks-on-the-embeds.md`);
  the package still carries no color.

## Units and names, as Basis sees them

| Concept | CSS (`cadence.css`) | Framer module | Unit |
|---|---|---|---|
| duration | `--cadence-duration-fast/base/slow/slower` | `durations.fast/base/slow/slower` | ms / s |
| easing | `--cadence-ease-linear/standard/enter/exit/overshoot` | `easings.*` (bezier array) | — |
| delay | `--cadence-delay-none/short/medium/long` | `delays.*` | ms / s |
| scale | `--cadence-scale-press-subtle/press-base/press-expressive/lift` | `scale.pressSubtle/pressBase/pressExpressive/lift` | unitless |
| spring | `--cadence-spring-stiffness/damping/mass` | `spring` (complete transition object) | unitless |
| scalar | `--cadence-duration-scalar` | absent | unitless |

Seams to respect: JSON says `easing`, runtime says `ease`, module says
`easings`. Basis only ever touches the module and the CSS, so in Basis code the
words are `easings` (JS) and `--cadence-ease-*` (CSS). Never introduce a third.

## Standard preset values (for review, not for hardcoding)

durations 100/200/400/600 ms · delays 0/50/100/200 ms · ease.standard
(0.4, 0, 0.2, 1) · enter (0, 0, 0.2, 1) · exit (0.4, 0, 1, 1) · overshoot
(0.34, 1.56, 0.64, 1) · scale 0.98/0.95/0.90/1.02 · spring 170/20/1.5.

## `useMotionTokens()` — the Basis-side adapter

`lib/motion/tokens.ts` exports one hook. It is the seam between Cadence and
every Basis component. `useMotionTokens(preset?)`: without an argument the
preset is the root's; with one, that preset, under the same reduced-motion
branch (the welcome is the one caller).

```ts
type MotionTokens = {
  durations: typeof durations   // flattened to 0.01 under reduced motion
  delays: typeof delays         // flattened to 0 under reduced motion
  easings: typeof easings       // unchanged
  scale: typeof scale           // unchanged
  spring: Transition            // Cadence spring, or { duration: 0.01 } under reduced motion
  springDamped: Transition      // the same spring critically damped, same reduced-motion branch
  transitions: typeof transitions  // REBUILT from the fields above, never the module's
  reducedMotion: boolean
}
```

Reduced-motion policy is `REDUCED_MOTION_RESOLUTION`: duration → 10 ms, delay →
0, easing/scale/spring/scalar unchanged. The spring branch is Basis's
responsibility (a spring has no duration to flatten): when `reducedMotion` is
true the hook returns `spring = { duration: 0.01 }` and every consumer of
`spring` goes through the hook, never the module. 10 ms, not 0, so
`onAnimationComplete` still fires.

`springDamped` is the Cadence spring with its damping raised to critical,
`2·√(stiffness · mass)`, so it settles with no overshoot. Every number in it
is the token's own; the relation is physics, not a tuned value. Cadence has
one spring and Basis cannot re-tune it, so a use that needs the spring's
motion without its bounce (the drawer) takes this derived one. If Cadence
grows a damped spring token, this field reads it instead. Under reduced
motion it takes the same 10 ms branch as `spring`.

`transitions` is the same trap one level up. The module evaluates
`transitions.enter = { duration: durations.base, ... }` at load, so the object
holds 0.2 no matter what the hook did to `durations`, and `transitions.spring`
is the live spring. The hook therefore rebuilds all three from its own
flattened fields:

```ts
transitions: {
  enter: { duration: durations.base, ease: easings.enter },   // hook's durations
  exit:  { duration: durations.fast, ease: easings.exit },
  spring,                                                     // hook's spring
}
```

The module's `transitions` export is never returned as-is. The provenance
popover and the command palette run on `transitions.*`, so without this they
would be the two interactions that ignore reduced motion.

`reducedMotion` is read from `document.documentElement.dataset.reduceMotion`,
set by the inline script in `layout.tsx` before hydration from the `?reduce=1`
override, then the stored choice (`basis-reduce`, written by the command
palette's toggle), then `matchMedia('(prefers-reduced-motion: reduce)')`.
The palette can turn reduced motion on at any time and off only when the
system does not ask for it: the package's media block flattens CSS timing
under the system preference whatever the attribute says, and Basis does not
restate Cadence's durations to undo it
(`decisions/2026-09-28-palette-scope.md`).
**Embeds are the exception** (`decisions/2026-10-14-reduce-0-on-the-embeds.md`):
on `/embed/*`, `?reduce=0` sets the attribute to `0` over the stored choice
and the system, and is never stored. There the inline script always sets
`data-preset` (`standard` when absent), and `styles/presets.css` restates each
preset's own durations and delays at `:root[data-reduce-motion='0'][data-preset]`,
generated from the package, so the media block cannot flatten what the visitor
asked to see.
CSS reads the package's own media block; the `[data-reduce-motion="1"]`
selector in `app/globals.css` mirrors the same resolution for the override case.

**Rows are opaque; on a sort they rise over and fall under, in lanes.** The
bands are each row's own fill and move with it (the passbook look David
chose over still bands, 2026-10-05). A row without a band is filled with the
paper, so a crossing row covers what it passes. Two references set the rest
(2026-10-05): an F1 timing tower, where a driver gaining a place lifts and
passes over the drivers losing it, and Scott Logic's ranking tables, where
rising and falling rows step into separate lanes before they travel. On
each sort a rising row steps a lane to the left and lifts to `scale.lift`, a
falling row steps a lane to the right, and both step back as they land
(the two rows above; the lane is Basis spacing, `--space-2`). Rows stack
rising over still over falling, and within each group the shortest move on
top, ties broken by name, so the rows that barely move stay legible. Text
stays visible throughout: the fade of 2026-10-05 is withdrawn, because the
table went blank and the moves lost their context (David). While a sort
runs the ledger's horizontal clip is lifted so a lane is not cut at the
edge; nothing resizes the table during a sort, which is what the clip is
for. The table body is its own stacking context, so these levels never
compete with the sticky header or the drawer.

**The theme switch is one crossfade.** It runs as a view transition of the
root (`document.startViewTransition`): the old page and the new one fade on
`base` / `standard`, read from `--cadence-duration-base` and
`--cadence-ease-standard` on the `::view-transition-old(root)` and
`-new(root)` pseudo-elements, so reduced motion flattens it like any CSS
duration. Every element's own transitions are suspended while it runs
(`[data-theme-switching]`), so nothing fades a second time inside it at its
own rate; before this, the drawer and the chart switched at once, the
ledger's bands on `fast`, the page on `base`, and the figures on `slower`
(David, 2026-09-28). Without the API the switch is instant, everywhere
together.

**Loops do not run under reduced motion.** Flattening a duration is right
for a transition, which then lands at its end in one frame. A looped
animation flattened to `0.01s` does not stop: it cycles a hundred times a
second and reads as a flicker. Every looped animation (the shimmer, the
refresh arrow) is removed under `[data-reduce-motion='1']` and holds a
still pose; its state is carried by what does not move (the tint, the
disabled button, `aria-busy`). David, 2026-09-28.

## The In Practice stage

`/embed/in-practice` is the stage Cadence's In Practice page frames: the
chart over the ledger, simplified (David, 2026-10-15,
`decisions/2026-10-15-the-in-practice-stage.md`). Four companies' Level
over one year, no controls, above the comps ledger. It takes the embeds'
`?preset=`, `?theme=` and `?reduce=` and their `frame-ancestors` header
unchanged, and it adds no interaction, so no row below: the lines draw in on
load (chart line draw-in), a row and its line light together both ways (row
hover / line hover), the ledger sorts as on the sheet (reorder, lane step).
The four charted rows are selected and stay so: every checkbox, the
header's included, is disabled, so the selection is the chart's and cannot
drift from it. Sort never touches the lines. It reads no Worker and runs no
refresh: its figures are a committed copy of a live snapshot, read at the
moment that snapshot was written, which the stage states. From 560 to
880 px wide it is 820 px tall, and Cadence sizes its frame to that. A
provenance panel that would lengthen the document opens above its figure.

The drawer is an intercepting route, so Next removes it from the tree the
moment history moves, on every close path: Escape, the close control, and
the back button alike. A DrawerExit in the root layout, which outlives the
slot, holds the removed element in its grid column and runs the close on it;
history itself moves at once and stays honest. What animates on open and
close is the drawer column's width, zero to the drawer's width and back, on
`springDamped`: the sheet beside it is the same layout, so the header, the
chart, the ledger, and the footnotes resize on the same curve with nothing
animated separately. The panel keeps its full width inside and the dialog
clips it, so nothing in the drawer rewraps. The ledger's `short` stagger is
for a reorder only. (The raw spring read as too springy; damping it, not
removing it; an instant close read as no exit; a translated panel over an
instant reflow read as a seam. David, 2026-09-16.)
A metric switch is not a rescale (`decisions/2026-10-19-a-metric-switch-redraws.md`).
The metrics have different units, Level about 100, Δ 1d in thousands of
bps, EV/EBITDA in tens, so a tween between their domains passes through
numbers that belong to neither, and the new values drawn on the old domain
for its first frame ran a line thousands of pixels past the plot, as it
had since M6 (David, 2026-10-19). On a switch the old ribbons, gridlines, y ticks,
and endpoints leave together on `fast` / `exit`, on the domain they were
drawn on; the domain is made new at the new metric's window, as a first
domain is, never animated; the new ticks and gridlines fade in at their
places on `base` / `enter`; and every charted ribbon draws in again from
the left on the draw-in row, staggered by selection order, its endpoint
landing as the draw reaches it. A range change within a metric still
rescales.
The chart's cursor (docs/spec.md, Chart): the rule, the dots, and the point
card enter and exit together on `transitions.enter` / `transitions.exit`,
and their position follows the pointer with no tween, since a tween there
reads as lag. The card is the pointer's affordance; the readout stays the
live region for keyboard users and hides while a cursor is up, so one row
never shows two values at once.
The diagnostics strip (docs/spec.md, Diagnostics): a tool's card enters
and exits on `transitions.enter` / `transitions.exit`, whether it floats on
hover or sits pinned under the chart. The window's shade, handles, and axis
tags appear and clear on `base` / `standard`; while the pointer drags, the
window follows it with no tween.
Switching the entity while the drawer is open does not reopen it: the text
scrambles per character into the new text over `slower`, with the glyph
clock on `delays.short`. The clock is one value and cannot ease; what
eases is the schedule: which characters are churning at each moment.
Progress runs through `standard` before it is compared to any character's
onset or settle moment, so the churn ramps in, settles mostly in the
middle, and the last characters resolve in a tail rather than at once.
Under reduced motion both flatten and the text simply changes.

The welcome dialog (`decisions/2026-10-15-a-welcome-on-landing.md`) enters
and exits as the command palette does, on `transitions.enter` /
`transitions.exit`, and its backdrop is there for as long as the element is
open, with no fade of its own. The Basis title inside it holds its own
timing, as the logos do.

The drawer's scroll cue (`decisions/2026-10-15-drawer-scroll-cue.md`)
stands in for the drawer's hidden scrollbar: a ↓ that bounces vertically
while the drawer has more below and clears at the bottom. It is not a
control. A hovering pointer stops the bounce where it is and lifts the
arrow; only where hover exists (`(hover: hover) and (pointer: fine)`).
Under reduced motion the bounce is removed (loops do not run) and the
arrow holds still.

The analysis views (M12; `docs/notes/2026-10-19-new-charts-motion.md`).
**The marker is the row across views.** A row's color and endpoint marker
are its identity on the line, so they stay on screen when the hero view
changes: from Over time to Risk / return each charted row's marker leaves
its endpoint and travels to its point on `slow` / `standard`, and back on
return, the domain rescale's pair. A tween, not the spring: the spring is
the drawer's, and its bounce would read as a value that has not settled.
Rows the line did not chart appear at their points on `base` / `enter`.
Nothing in Basis runs `overshoot`. (David, 2026-10-19.)
**Time arrives from the left.** The heat grid and the projection fan
reveal as the line draws in, by a clip widening across the plot, so every
view reads time in one direction. Line to heat carries nothing across,
since heat has rows and no markers: the ribbons leave on the outgoing
view's `fast` / `exit` and the grid reveals on the draw-in row. A cell
click goes the other way: the view switches to Over time, the row is
charted, and the window takes that bucket; the window's shade lands on
`base` while the line draws on `slower`, so the week is framed before the
line fills it. Re-bucketing on a range change is a crossfade, because a
week's cell cannot become a month's.
**The fan waits for today.** It opens only once the line's draw-in has
reached the last point, the 50% band first and the 90% tint `short` after.
Toggled off, it closes into the today rule. It never loops.
**The waterfall builds once.** On the card's entry the steps build start
to end, each from the last step's level, `medium` apart. A window change
afterwards re-tweens the bars in place; it does not replay the build.
**The bar follows the sort, and stays where it is kept.** A figure
column shows its bars while it is sorted, and whatever the sort while its
header's keep box is checked (`decisions/2026-10-19-bars-can-be-kept.md`).
Every figure column keeps its track, pinned to the cell's leading edge,
so the zero rule is one line down the column and nothing reflows when
bars come or go. A column gaining bars grows them on `slow` / `enter`
with the row's `short` stagger; when the sort moved, the rows reorder in
the same moment, so bars and rows land together. A column losing them
retracts on `fast` / `exit`. Where the ledger gives up columns (an open
drawer) the bars give way first; when it widens again they return as a
fade on `base` / `enter`, a CSS entry with no effect behind it.
Under reduced motion every one of these flattens through
`useMotionTokens()`: markers land in place, the grid and the fan are
simply there, the waterfall shows whole. None of them loops.

Rive artboards (`AgentPresence`, logos) hold their own timing inside the state
machine; Basis pushes only view-model values. The `reduced` boolean in the
view model is set from the same `reducedMotion` flag.

## `useAnimatedNumber(value, format)`

Basis-side for now. Interpolates a `MotionValue<number>` to `value` on change
using `durations.slow` / `easings.standard`, renders through `format`.
Candidate to upstream into Cadence if Token Lab's live retiming turns out to be
the same behavior; note it as such in the README and do not upstream from this
repo.

## Lint

`eslint/no-inline-motion.js` flags numeric literals and non-token identifiers
in timing positions only. A target is not a timing position:
`animate={{ opacity: 1 }}` is fine, `transition={{ duration: 0.3 }}` is not.

JSX and JS: the value of every timing key, `duration`, `delay`, `stiffness`,
`damping`, `mass`, `repeatDelay`, `staggerChildren`, `delayChildren`, wherever
it appears: a `transition` prop, a `transition` key nested inside `animate`,
`initial`, `exit`, `whileHover`, `whileTap`, or a variants object, and the
options argument of `animate()`. An `ease` value must be an identifier, never
a string or an array literal.

CSS Modules: the time components of `transition`, `transition-duration`,
`transition-delay`, `animation`, `animation-duration`, `animation-delay`, and
any `cubic-bezier()` or keyword easing in those declarations.

Allowed identifiers resolve to `useMotionTokens()` fields or `var(--cadence-*)`.
This is the Cadence gate (`src/tokens/tokenIntegrity.test.js` there) in its
Basis form; its fixtures are the M1 planted literal and one clean file per
shape above.
